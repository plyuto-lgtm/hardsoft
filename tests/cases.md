# Cases to check after changing the skill

The calculator has its own tests: `node --test`. These cases are for the instructions. After an edit to `SKILL.md` or `approach.md`, give the skill each case and check that it does what the line says.

| # | Case | It must | Rule |
| --- | --- | --- | --- |
| 1 | "Is hardsoft worth it for this project?" | Run report. Interview first, 3 to 6 questions with options made from the real names found. Change no token. End by offering apply. | 30 |
| 1a | The user skips the interview. | Go on with guesses, each marked "Assumed" in the report. | - |
| 1b | Any report. | The first screen says if it is worth it, what is won and what stays the same, with no rule numbers. Details are below the line. | - |
| 2 | "Apply hardsoft." | Report, questions in one message, plan and preview, then wait for a yes. | 30 |
| 3 | Light-only product, nobody mentions dark mode. | Never add or propose a theme. | 21 |
| 4 | "Add dark mode", system still on solid grays. | Say apply comes first. One plan for both. | 21 |
| 5 | Five slightly blue grays, a pure black ink. | Offer a tinted ink with both sides of the cost. Change it only after a yes. | 4 |
| 6 | One odd gray that fits no step. | Keep it, list it, ask. Never move it silently. | 23 |
| 7 | Brand ramp 50 to 900, the 900 used for text. | Tints become the master at steps. Offer 900 as a second master. Unused shades are removable. | 5 |
| 8 | A sidebar beside the content. | Soft. | 12 |
| 9 | A sticky header that content scrolls under. | Hard. | 12 |
| 10 | Stacked avatars, a badge on a card corner. | Hard. | 12 |
| 11 | A button on a brand banner. | Soft: the ink or the brightest gray at a step. | 13 |
| 12 | A label on a photo. | Hard: solid, or blur with a token. | 13 |
| 13 | The system has pressed and disabled states. | Keep their design. Rebuild only the colors. Invent no state. | 19 |
| 14 | Hex values inside components. | Don't edit them. List each with its token. | 27 |
| 15 | `surface-1` and `surface-2` end up the same. | Both names keep working. Listed as removable. | 17, 26 |
| 16 | Fewer steps or the same look. | Show both with numbers. Recommend neither. | 8 |
| 17 | Secondary text fails AA three cards deep. | List it with its ratio. Offer the nearest stronger step. | 28 |
| 18 | Shadows and a gradient. | Shadow color becomes a gray at a step, shape untouched. Gradient is left out and listed. | 22, 29 |
| 19 | A transparent border on a card with a transparent fill. | Measure it over what it lies on. Add a hairline token. List the border to move, don't edit it. | 16, 27 |
| 20 | A menu and a raised panel with their own solid grays. | Keep them solid, with their names. Don't make them masters or steps. | 14 |
| 21 | Any report. | Open with independent tokens before and after, and the closeness percent. | - |
| 22 | The app runs locally and npx is allowed. | Capture real screens with census before and after. Run `shift` on what changed. Fix anything that is not a color. | - |
| 25 | The project's own rules forbid new tokens. | Follow the project. Name the clash in the plan. | - |
| 23 | Tokens in a Tokens Studio JSON file. | Write that format. Keep the link to the master. Say the design source needs the same change. | - |
| 24 | The system already uses one ink and alphas. | Say there is little to win, with the numbers, and stop. | - |
